# 7단계. 서버 저장 (Firebase)

- 권장 모델: Opus 5.5 / effort high
- 이유: 로그인·보안 규칙·로컬 데이터 이전은 실수 시 데이터 유출이나 손실로 이어짐. 작업량은 작음.
- 읽을 파일: `00-overview.md`, 이 파일, `src/db.ts`, `src/types.ts`

## 사전 조건 (사용자가 먼저 해야 함)
- Firebase 프로젝트 생성(Spark 무료), 웹 앱 등록, Authentication에서 Google 로그인 활성화, 승인된 도메인에 `minniekorean-sketch.github.io` 추가. Claude가 단계별 안내문을 먼저 보낸다.
- 시작 전에 Firebase Spark 무료 한도와 정책을 다시 확인하고, 유료 전환 가능성이 있으면 사용자에게 먼저 알린다.

## 작업
1. Google 로그인. 로그인하지 않아도 로컬로 계속 쓸 수 있게 유지.
2. Firestore 오프라인 지속성 사용. 경로 `users/{uid}/...`.
3. 보안 규칙: 본인 uid 데이터만 읽기·쓰기. 규칙 파일을 저장소에 포함.
4. 첫 로그인 시 IndexedDB 데이터를 Firestore로 1회 이전 (중복 방지).
5. Firebase 웹 설정값은 공개 값이므로 코드에 포함 가능. 서비스 계정 키 등 비밀값은 사용하지 않는다.

## 완료 기준
- 보안 규칙 에뮬레이터 테스트: 다른 uid 접근 거부.
- 기존 로컬 데이터 이전 확인.

## 사용자 확인 필요 사항
1. (시작 전) 위 사전 조건 완료와 Firebase 웹 설정값 전달.
2. (끝) 다른 기기 또는 브라우저에서 로그인해 같은 데이터가 보이는지.
3. 이전 후 과거 기록이 빠짐없이 남아 있는지.
4. PR 승인·머지.
