# 3단계. 메뉴 라이브러리 작성 (40~60개)

- 권장 모델: Sonnet 5.5 / effort medium
- 이유: 레시피 품질(아이 안전, 한국어 표현)이 필요해 Haiku는 부적합. 분량이 많아 Opus는 비용 대비 이득이 작음.
- 읽을 파일: `00-overview.md`, 이 파일, `src/types.ts`, `src/data/ingredients.json`

## 진행 방식 (토큰 절약)
- **3-1. 메뉴 목록만 먼저**: 이름·요리 종류·단백질·예상 작업/총 시간만 표로 50개 제안 (레시피 본문 없음). 사용자 승인 후 3-2 진행.
- **3-2. 레시피 본문은 10개씩 배치**로 `src/data/recipes/batch-01.json` … 에 작성. 배치마다 `npm run validate:data` 통과 후 커밋. 한 세션에서 앞 배치 파일을 다시 읽지 않는다.
- 새 재료가 필요하면 `ingredients.json`에 추가 (기존 재료와 중복 확인은 Grep).

## 구성 기준
- 00-overview의 메뉴 규칙 준수 (매운 음식 금지, 작업 30분·총 90분 이내).
- 요리 종류별 최소 개수: 한식 10, 이탈리아식 10, 기타 유럽식 8, 일식 6, 구이·찜 8.
- 총 조리 시간 45분 이내 메뉴 최소 15개 (주말 2끼 × 2주 반복 없이 + 요리 종류·생선 규칙을 함께 채우기 위함).
- 단백질별 최소 개수: 생선 8 (주 1회 이상 생선 규칙을 2주 반복 없이 채우기 위함), 소 8, 닭 8, 돼지 6, 새우·조개 5.
- 기존 선호 메뉴 포함: 라구파스타, 수제햄버거, 소보로덮밥, 소고기무국, 미역국, 구운생선, 이탈리아식 대구찜, 새우 페스토파스타, 구운새우, 닭고기 버섯 리소토.
- 아이용 손질(방울토마토 4등분 등)은 조리 순서 안에 한 줄로.

## 완료 기준
- 레시피 40~60개, 검증 스크립트 통과, 위 최소 개수 충족 (검증 스크립트에 개수 집계 출력 추가).

## 사용자 확인 필요 사항
1. (3-1 끝) 메뉴 50개 목록 표: 빼거나 바꿀 메뉴, 아이가 안 먹는 재료.
2. (3-2 끝) 무작위 레시피 3개 전문: 분량과 작업 시간이 현실적인지.
3. PR 승인·머지.
